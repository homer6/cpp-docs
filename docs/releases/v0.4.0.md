# cpp-docs v0.4.0

The Core Guidelines release. Every rule of the C++ Core Guidelines is now in
the docs, and each has our own BAD/GOOD example or the reason it has none. The
BAD examples are compiled, and those that are undefined behaviour are run
under the sanitizers to prove it. The whole suite also runs under
AddressSanitizer, UBSan and ThreadSanitizer, and Clang 23 joins the platform
runs.

> **Re-released** on 2026-11-03 with corrected
> [platform support notes](../platform-support/notes.md)
> ([#350](https://github.com/homer6/cpp-docs/issues/350)). The first `v0.4.0`
> tag (`d45462a`) shipped notes in which several claims hadn't been re-checked
> against the release run: the MSVC page-record skip count, `[[assume]]` on
> MSVC 19.51, the private module fragment on MSVC, libc++ 23's additions and
> the GCC 15 range. The tag now points at the re-release. Nothing else changed:
> the tests, snippets and results are the same.

Tracking issue: [#273](https://github.com/homer6/cpp-docs/issues/273). The
results are in [`docs/platform-support.md`](../platform-support.md) and the
[platform support notes](../platform-support/notes.md), regenerated from the
release run.

## What's new

- **Every Core Guidelines rule**
  ([#233](https://github.com/homer6/cpp-docs/issues/233),
  [#234](https://github.com/homer6/cpp-docs/pull/234)).
  [`docs/guidelines/core-guidelines/`](../guidelines/core-guidelines/README.md)
  is generated from the pinned Guidelines: one page per official section, 529
  entries in official order, each with its ID, title, official link and the
  pages of ours that cite it. `tools/gen_core_guidelines.py --check` fails if
  a rule is missing or a page is stale. It links rather than copies, as the
  Guidelines' licence requires.
- **An example and a test for every rule**
  ([#235](https://github.com/homer6/cpp-docs/issues/235),
  [#242](https://github.com/homer6/cpp-docs/pull/242),
  [#254](https://github.com/homer6/cpp-docs/pull/254)–[#261](https://github.com/homer6/cpp-docs/pull/261)).
  Of the 513 numbered rules, 482 have our own BAD/GOOD example in
  [`examples/`](../guidelines/core-guidelines/examples/README.md), 31 aren't
  about code and say why, and 360 have a unit test in `tests/guidelines/`
  (362 tests).
- **BAD examples are checked, not skipped**
  ([#262](https://github.com/homer6/cpp-docs/issues/262),
  [#268](https://github.com/homer6/cpp-docs/pull/268)). New fence tags:
  - `bad`: compiles but is wrong; it must compile;
  - `bad warns="regex"`: the compiler must also warn;
  - `run`: a block with `main` is built with ASan + UBSan and must run clean;
  - `bad run`: a sanitizer must catch it.

  "This is UB" is now demonstrated, not asserted.
- **The suite under the sanitizers**
  ([#263](https://github.com/homer6/cpp-docs/issues/263),
  [#271](https://github.com/homer6/cpp-docs/pull/271)): the `clang-22-asan`
  and `gcc-16-asan` presets, and CI jobs for ASan + UBSan (GCC 16, Clang 22,
  macOS LLVM 23) and TSan (Clang 22 with libstdc++). A test that can't work
  under a sanitizer skips with the reason.
- **Clang 23 in CI** ([#266](https://github.com/homer6/cpp-docs/pull/266)):
  apt.llvm.org Clang 23 with libstdc++ and libc++ on Ubuntu 24.04 x86_64 and
  arm64.
- **Skills:** `modern-cpp` checks support against the measured results, with
  an eval suite ([#264](https://github.com/homer6/cpp-docs/pull/264));
  `cpp-guidelines` finds rules reliably and links our examples, with 31 eval
  cases ([#265](https://github.com/homer6/cpp-docs/pull/265)).
- **MIT License** ([#237](https://github.com/homer6/cpp-docs/pull/237)).
- **Fixes found by the runs:** snippets checked under `LC_ALL=C` so GCC's
  quotes match ([#277](https://github.com/homer6/cpp-docs/pull/277)), T.49's
  `on_exit` renamed because glibc declares it
  ([#279](https://github.com/homer6/cpp-docs/pull/279)), the private module
  fragment built on MSVC ([#240](https://github.com/homer6/cpp-docs/pull/240)),
  and sanitizer-specific skips ([#276](https://github.com/homer6/cpp-docs/pull/276),
  [#285](https://github.com/homer6/cpp-docs/pull/285)).

## What it does not include

- The security section (`docs/security/`) is v0.5.0's; its PRs target
  `dev-0.5`, not this release.
- The local Clang stays on 22.1.8: the Homebrew LLVM 23 move is blocked
  ([#272](https://github.com/homer6/cpp-docs/issues/272)). CI runs Clang 23.
- Clang 23 isn't run on Intel macOS (no Homebrew bottle or LLVM build).
- TSan runs on Linux with libstdc++ only; packaged libc++ isn't
  TSan-instrumented.
- Everything v0.3.0 listed as not included still holds (no emulated
  platforms; snippets enforced only where a reviewed baseline exists).

## Known issues

No security-relevant issues. Found by the release run, none blocking (report-only
snippets, warnings, a test gate):

- [#337](https://github.com/homer6/cpp-docs/issues/337): the structured-binding-as-condition test gates on 202403L instead of 202406L, so Clang 19/20 and Apple Clang 17 run it as an extension.
- [#338](https://github.com/homer6/cpp-docs/issues/338): a `signals.md` run block fails on Windows (handler reset to `SIG_DFL`).
- [#339](https://github.com/homer6/cpp-docs/issues/339), [#340](https://github.com/homer6/cpp-docs/issues/340): compile-fail regexes too narrow on some toolchains; clang-cl snippets lack `-pedantic-errors`.
- [#341](https://github.com/homer6/cpp-docs/issues/341): `known-bugs.json` entries to add or widen.
- [#342](https://github.com/homer6/cpp-docs/issues/342), [#345](https://github.com/homer6/cpp-docs/issues/345): a CI job name, and warnings in our test sources.

Compiler and platform bugs without an upstream report yet (filing waits for
