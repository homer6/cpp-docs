# cpp-docs v0.3.0

The platform support release. Every example and documented feature is now
tested on Linux, macOS, Windows and FreeBSD, with GCC, Clang, Apple Clang,
MSVC and clang-cl, on x86_64 and arm64: 47 toolchains in GitHub Actions plus
the three local ones. The results are published as a support report, one page
per toolchain.

Tracking issues: [#217](https://github.com/homer6/cpp-docs/issues/217) (this
release) and [#140](https://github.com/homer6/cpp-docs/issues/140) (platform
support).

## What's new

- **The support report.** [`docs/platform-support.md`](../platform-support.md)
  has the platform summary, a feature support matrix (every area per
  compiler), the compiler and platform bugs found, and the known gaps. Each
  toolchain has its own page in
  [`docs/platform-support/`](../platform-support/README.md), listing every
  area, page, feature and example with ✅, ❌ or ⏭ and the skip reason. The
  README links it under the badges and ends with the generated "Tested
  platforms" table.
- **The platform support notes**
  ([`docs/platform-support/notes.md`](../platform-support/notes.md),
  [#226](https://github.com/homer6/cpp-docs/issues/226)): a short reading of
  the results per compiler, platform and architecture, at the top of the
  toolchain index and linked from the README. In short: 0 test failures on 50
  toolchains; the standard library and compiler version decide the level of
  support, not the OS or CPU; GCC 16 is the most complete.
- **Platform workflows**, manual only (`workflow_dispatch`, each run started
  with the owner's consent): `linux.yml`, `macos.yml`, `windows-msvc.yml`,
  `windows-gnu.yml`, `freebsd.yml`, and `all.yml` to run them together
  ([#153](https://github.com/homer6/cpp-docs/pull/153),
  [#157](https://github.com/homer6/cpp-docs/pull/157),
  [#158](https://github.com/homer6/cpp-docs/pull/158)).
  - Linux, x86_64 and arm64: GCC 13-16 (the official `gcc` images, Debian
    12 and 13), Ubuntu 26.04's GCC 15, and Clang 18-22 with libc++ and with
    libstdc++ (apt.llvm.org on Ubuntu 24.04, the archive on 26.04).
  - macOS 15 and 26, arm64 and Intel: Apple Clang, Homebrew GCC 16 and
    Homebrew LLVM.
  - Windows: MSVC (VS 2022 and VS 2026, x64 and arm64), clang-cl, and MSYS2
    (UCRT64 GCC and Clang with libstdc++, CLANG64 Clang with libc++).
  - FreeBSD 14.5 and 15.1 (x86_64) in a VM: the base Clang and pkg GCC 14.
- **A portable build and checker**
  ([#156](https://github.com/homer6/cpp-docs/pull/156)): CMake presets and
  `tools/run_tests.ps1` for MSVC, clang-cl and MinGW; `check_snippets.py`
  drives cl-style compilers; per-toolchain snippet baselines.
- **The test suite runs everywhere.** Missing features skip with the
  feature-test macro or the compiler bug that blocks them, never vanish.
  The build detects the standard library from its own macros and links
  libatomic and libstdc++exp where a toolchain needs them
  ([#165](https://github.com/homer6/cpp-docs/pull/165)–[#213](https://github.com/homer6/cpp-docs/pull/213)).
- **Tools:** `tools/collect_results.py` builds the report from consented runs
  and keeps their results in
  [`docs/platform-support/runs/`](../platform-support/runs/), compact and
  limited to the runs the report uses
  ([#187](https://github.com/homer6/cpp-docs/pull/187),
  [#214](https://github.com/homer6/cpp-docs/issues/214));
  `tools/feature_support.py` builds the matrix and the toolchain pages.
- **The `platform-support` skill**
  ([#189](https://github.com/homer6/cpp-docs/pull/189)) plans the runs, reads
  every job's log, captures each finding in the suite, files one issue per
  vendor bug, and regenerates the report.
- **Page fixes found by the runs**, for example `std::text_encoding` isn't in
  libstdc++ on MinGW ([#212](https://github.com/homer6/cpp-docs/pull/212)),
  and the barrier in `coordination.md` no longer clashes with POSIX `sync()`
  ([#199](https://github.com/homer6/cpp-docs/pull/199)).
- **Guidelines:** the GSL in industry practice, and the Guidelines' GSL rules
  ([#155](https://github.com/homer6/cpp-docs/pull/155)).

## What it does not include

- No emulated platforms (riscv64, s390x, ppc64le were removed in
  [#208](https://github.com/homer6/cpp-docs/pull/208)), and no FreeBSD arm64.
- No GCC or Clang on Windows arm64; MSVC is the only arm64 Windows
  toolchain.
- Module snippets aren't checked with MSVC or clang-cl, and Apple Clang can't
  build the named-module tests (no `clang-scan-deps`).
- Snippets are enforced only where a reviewed baseline exists (GCC 15 and 16,
  Clang 22 with libc++). Elsewhere they're report-only: the failures are
  support data in the report, not run failures.
- No compiler implements hive, senders, linalg, simd or RCU/hazard pointers
  yet; reflection and contracts run on GCC 16 only.

## Known issues

No security-relevant issues. Five compiler and platform bugs have no upstream
report yet; each has its own issue, and filing upstream waits for the
owner's yes ([#185](https://github.com/homer6/cpp-docs/issues/185)):

- [#218](https://github.com/homer6/cpp-docs/issues/218): libc++ 19/20,
  `ranges::contains` over `views::join` of a 2-D array finds a missing value.
- [#219](https://github.com/homer6/cpp-docs/issues/219): pkg GCC 14.2 on
  FreeBSD 15.1 crashes on every module unit (the module tests skip there).
- [#221](https://github.com/homer6/cpp-docs/issues/221): Homebrew GCC 15 on
  macOS, `std::nested_exception` doesn't capture the current exception.
- [#222](https://github.com/homer6/cpp-docs/issues/222): MSVC 19.51 claims
  P2718 but destroys range-for temporaries early.
- [#223](https://github.com/homer6/cpp-docs/issues/223): MSVC 19.44 rejects
  constexpr virtual calls (fixed in 19.51).

Every bug found, with its upstream link where one exists, is in the report's
"Compiler and platform bugs found" table. The Clang 22 + libc++ baseline lists
19 libc++ gaps (17 on Linux); the GCC baseline is empty.
