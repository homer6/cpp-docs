# cpp-docs v0.2.0

A minor release that fills the gaps found by the 2026-11-01 coverage audit
([#92](https://github.com/homer6/cpp-docs/issues/92)). It adds 7 pages and new
sections across 13 areas, with C++23/26 language and library features, a
constexpr deep dive and more reflection. It also adds two skills: one for
adding to the reference and one for writing C++ with it.

Tracking issue: [#124](https://github.com/homer6/cpp-docs/issues/124).
Previous release: [v0.1.0](v0.1.0.md).

### Late C++26 changes the pages follow

Each change was verified against its paper and on the local toolchains:

- `views::to_input` was renamed `views::as_input` (P3828R1). GCC 15 has the
  old name and GCC 16 the new one.
- `add_sat` and its siblings were renamed `saturating_add` and so on (P4052R0,
  `__cpp_lib_saturation_arithmetic` 202603L). Only GCC 16 has the new names.
- `submdspan`'s `strided_slice` was replaced by `extent_slice`/`range_slice`
  (P3982R2).
- `function_ref` binds a function with `std::cw<f>` (P3948R1).
- `exception_ptr_cast` now returns `optional<const E&>` (P3981R2). GCC 16 still
  returns `const E*`, so the page shows both.
- `localtime_r`, `gmtime_r` and `timegm` are standard in C++26 (P3348R4). No
  local library declares them in `std::` yet.

### Skills and workflow

- **`add-to-topic`** ([#91](https://github.com/homer6/cpp-docs/pull/91),
  [#128](https://github.com/homer6/cpp-docs/pull/128)) adds an idea to the
  reference:
  - a coverage check;
  - research with Perplexity and Firecrawl, starting with cppreference;
  - how to consult the standard and WG21 papers;
  - checking published compiler support (GCC, Clang, MSVC);
  - verification on all three toolchains with `probe.py`;
  - placement, the snippet and its test.
- **`modern-cpp`** ([#127](https://github.com/homer6/cpp-docs/pull/127)) writes
  C++ with this reference, here or in another project. It covers the project's
  constraints, the right pages, toolchain support, the guidelines and
  validation.
- **CLAUDE.md**:
  - an issue runs only its applicable tests, and the full suite runs before a
    release ([#112](https://github.com/homer6/cpp-docs/pull/112));
  - every PR keeps the README index and CLAUDE.md current
    ([#116](https://github.com/homer6/cpp-docs/pull/116));
  - compiler-support pages ([#128](https://github.com/homer6/cpp-docs/pull/128)).

## What it does not include

- **Not checked on MSVC or Windows.** MSVC support is described from
  Microsoft's published pages where a page mentions it.
- **No local compiler implements:** `std::hive`, senders/receivers,
  `std::linalg`, `std::simd`, RCU and hazard pointers, and the private module
  fragment. Those snippets are tagged `needs=` and their tests skip.
- **Reflection** is verified on GCC 16 with `-freflection` only. GCC 15 and
  Clang 22 have no `<meta>`.

## Known issues

No security-relevant issues. No issues are open.

- **Clang 22 + libc++:** 19 snippets fail on genuine libc++ gaps (v0.1.0: 12),
  all listed in `tools/snippet_baseline/clang.txt`. The new ones are libc++
  gaps the new content uses: ranges folds and `cartesian_product`,
  `spanstream`, `<stdbit.h>` and `is_layout_compatible`. The GCC baseline is
  empty.
- **Homebrew GCC 15 on macOS:** `std::call_once` with a throwing callable
  terminates instead of retrying (libstdc++ PR 66146). That test skips there.
  The existing `nested_exception` skip remains too.
- **Run Docker natively.** The first GCC 16 run of this release used an amd64
  `gcc:16` image under Rosetta, where `BadCastAndBadAlloc` traps instead of
  throwing `std::bad_alloc`. Natively it passes. `run_tests.sh` and `probe.py`
  now pass the host's `--platform`
  ([#130](https://github.com/homer6/cpp-docs/issues/130)).
- **No CI.** The proof below is from local runs.
