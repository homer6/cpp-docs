# cpp-docs v0.5.0

The security release. A new section, [`docs/security/`](../security/README.md),
teaches how to write C++ that holds up against an attacker: trust boundaries,
untrusted input, sizes and bounds, lifetimes across callbacks, fail-closed
errors, secrets, process and file boundaries, resource limits, hardening,
verification, the supply chain, deployment and policy. Every page was checked
against primary sources and our compilers, and its checkable claims have
tests. The section starts from what makes C++ secure: code written to the
Core Guidelines, library hardening, verification and a small trusted core.

> **Re-released** on 2026-11-04 with
> [`tools/release_notes.py`](../../tools/release_notes.py)
> ([#390](https://github.com/homer6/cpp-docs/issues/390),
> [#391](https://github.com/homer6/cpp-docs/pull/391)), at the owner's
> request ([#392](https://github.com/homer6/cpp-docs/issues/392)). The first
> `v0.5.0` tag (`f97b460`) is the same release without it. It changes no C++,
> test or workflow, so the runs below still hold.

Tracking issues: [#363](https://github.com/homer6/cpp-docs/issues/363) (this
release) and [#286](https://github.com/homer6/cpp-docs/issues/286) (the

## What's new

- **`docs/security/`: 17 verified pages**
  ([#311](https://github.com/homer6/cpp-docs/pull/311),
  [#314](https://github.com/homer6/cpp-docs/pull/314),
  [#316](https://github.com/homer6/cpp-docs/pull/316)–[#326](https://github.com/homer6/cpp-docs/pull/326),
  [#330](https://github.com/homer6/cpp-docs/pull/330),
  [#333](https://github.com/homer6/cpp-docs/pull/333),
  [#335](https://github.com/homer6/cpp-docs/pull/335),
  [#336](https://github.com/homer6/cpp-docs/pull/336),
  [#358](https://github.com/homer6/cpp-docs/pull/358)).
  - **Format:** each page has a mental model and **MUST** / **SHOULD** rules with their reasons.
  - **Citations:** Core Guidelines IDs and SEI CERT IDs (cited and linked, never copied), plus vendor documentation and man pages for the facts.
  - **Code:** our own compile-checked examples, including `bad run` blocks that ASan or UBSan must catch.
  - **Tests:** a test file per page in `tests/security/` (18 files, 80 tests).
  - **Findings:** the pages record what we measured, for example:
    - which standard library ships `std::memset_explicit` (none);
    - that `std::hash` is unsalted in libstdc++ and libc++;
    - that libstdc++ turns its assertions on by default only at `-O0`;
    - that Homebrew GCC 15's `pac-ret` breaks exception unwinding on macOS
      ([#327](https://github.com/homer6/cpp-docs/issues/327)).
- **The `cpp-security` skill**
  ([#315](https://github.com/homer6/cpp-docs/pull/315)). It reviews code where
  an attacker controls input, attack first. It hardens a build for the
  library actually linked, and plans the security tests.
  - `modern-cpp` and `cpp-guidelines` hand security work to it and carry a
    short checklist ([#346](https://github.com/homer6/cpp-docs/pull/346)).
  - Nine eval cases in `evals/cpp-security/`: seven exploitable bugs, a
    compliant control and one that needs the trust boundary. `evals/check.py`
    checks every cited anchor.
- **Hardened builds**
  ([#328](https://github.com/homer6/cpp-docs/pull/328),
  [#329](https://github.com/homer6/cpp-docs/pull/329)).
  - `CPPDOCS_HARDEN` adds library hardening for whichever library is in use,
    stack protection, zero-initialized locals, control-flow protection,
    `_FORTIFY_SOURCE=3`, PIE and full RELRO, each flag probed first.
  - Presets `gcc-15-hardened`, `clang-22-hardened` and `gcc-16-hardened`, and
    hardened CI jobs on Linux, macOS and MSVC.
  - Death tests show each library check stopping an out-of-range access.
- **Fuzzing** ([#331](https://github.com/homer6/cpp-docs/pull/331)).
  - libFuzzer targets for the pages' parsers, a CI fuzz job, and a saved
    corpus replayed as tests on every toolchain.
  - Its first run found a bug in the parsing page's own code: `"05"` was
    accepted as port 5.
  - Coverage of the rejection paths found two corpus gaps
    ([#333](https://github.com/homer6/cpp-docs/pull/333)).
- **clang-tidy** ([#332](https://github.com/homer6/cpp-docs/pull/332)): a
  Core Guidelines, CERT and bugprone profile over the security tests and fuzz
  targets, with every finding an error, a runner script and a CI job.
- **CLAUDE.md**
  ([#347](https://github.com/homer6/cpp-docs/pull/347),
  [#360](https://github.com/homer6/cpp-docs/pull/360),
  [#362](https://github.com/homer6/cpp-docs/pull/362)):
  - the security section's conventions;
  - security pages are C++ first, but not C++ only;
  - don't harden this repo unnecessarily;
  - stacked PRs;
  - no AI attribution anywhere, with the check to run;
  - never merge a PR labelled `rejected`.

- **CI: start only the jobs you need**
  ([#377](https://github.com/homer6/cpp-docs/pull/377)). Every platform
  workflow and `all.yml` take a `jobs` input, a regex for the job names to
  start, so a fix-up run starts only the jobs that failed on the fixed commit.
  - Each workflow's jobs are listed in `.github/ci/<workflow>.json`; a `plan`
    job selects from the list, and `tools/ci/plan.py` previews a pattern.
  - `check_workflows.py` checks that each workflow and its list agree.
  - The report keeps each job from the newest run that ran it.
- **GitHub release text** ([#391](https://github.com/homer6/cpp-docs/pull/391)):
  `tools/release_notes.py vX.Y.Z` prints a notes page ready for a GitHub
  release, which shows every newline as a line break. It joins the wrapped
  lines and makes relative links absolute at the tag. Every release
  description from v0.1.0 on was rewritten with it.
- **Found and fixed by the release runs** (each an issue and a PR):
  - pages: the bounds and bad-downcast examples are now caught by a sanitizer
    on every library ([#366](https://github.com/homer6/cpp-docs/pull/366),
    [#374](https://github.com/homer6/cpp-docs/pull/374)); `ckd_add` is gated
    on `__cpp_lib_stdckdint_h`, because GCC 14.2's `<stdckdint.h>` is C-only
    ([#373](https://github.com/homer6/cpp-docs/pull/373)); the `Secret`
    formatter's `format` is a template, because libc++ 18 rejects a
    `format_context`-only one ([#385](https://github.com/homer6/cpp-docs/pull/385));
    MSVC's `/sdl` and C4996 are explained
    ([#383](https://github.com/homer6/cpp-docs/pull/383)); the cfenv page
    records GCC's `rint` expansion at `-O2`
    ([#375](https://github.com/homer6/cpp-docs/pull/375));
  - tests and build: `-frounding-math` for the cfenv tests on GCC and
    `FENV_ACCESS` on Clang ([#375](https://github.com/homer6/cpp-docs/pull/375),
    [#382](https://github.com/homer6/cpp-docs/pull/382)); the hardened MSVC
    build ([#383](https://github.com/homer6/cpp-docs/pull/383),
    [#386](https://github.com/homer6/cpp-docs/pull/386)); clang-tidy
    ([#381](https://github.com/homer6/cpp-docs/pull/381)); a fuzz corpus file
    named `nul`, which Windows can't check out
    ([#372](https://github.com/homer6/cpp-docs/pull/372)); the link checker
    ([#367](https://github.com/homer6/cpp-docs/pull/367)).

## What it does not include

- Parts of the security section that need a future standard or a vendor
  aren't claimed: the pages say what isn't verifiable yet (for example the
  contracts status after the C++26 DIS ballot,
  [#313](https://github.com/homer6/cpp-docs/issues/313)).
- The local Clang stays on 22.1.8: the Homebrew LLVM 23 move is blocked
  ([#272](https://github.com/homer6/cpp-docs/issues/272)). CI runs Clang 23.
- The fuzz build on Apple drops UBSan
  ([#354](https://github.com/homer6/cpp-docs/issues/354)).
- Faster snippet checks with a precompiled prelude come after this release
  ([#387](https://github.com/homer6/cpp-docs/issues/387)).
- Everything v0.4.0 listed as not included still holds (no emulated
  platforms; TSan with libstdc++ only; snippets enforced only where a
  reviewed baseline exists).
