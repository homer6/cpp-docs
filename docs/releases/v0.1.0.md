# cpp-docs v0.1.0

The first release: a modern C++ (C++11 → C++26) reference organised the way
cppreference organises the language and library. It comes with opinionated
guidelines, a GoogleTest suite that checks what the pages claim, and the
tooling that keeps the snippets compiling.

Tracking issue: [#83](https://github.com/homer6/cpp-docs/issues/83).

### Guidelines: 12 pages in [`docs/guidelines/`](../guidelines/README.md)

The pages are Core Guidelines digest, memory & safety, modern idioms, design
principles, project conventions, industry practice, tooling (sanitizers and
static analysis), debugging (gdb and lldb), Valgrind, performance tooling,
testing, and build and packaging. Sources and edition dates are in
[`sources.md`](../guidelines/sources.md).

### Tests and tools

- **Test suite** ([`tests/`](../../tests)): 152 GoogleTest files with one
  executable per area, run with `tools/run_tests.sh gcc-15 | clang-22 | gcc-16`.
  A test whose feature the toolchain lacks is skipped with its reason, never
  dropped.
- **Snippet checker** (`tools/check_snippets.py`): compiles every C++ fence in
  the docs. Fences can be tagged `body`, `nocompile`, `compile-fail="regex"`,
  `needs=X` or `module`. Known failures are kept in per-compiler baselines.
- **Index generator** (`tools/gen_index.py`): writes the README index from the
  pages. `--check` fails when the index is stale.
- **Skills:** `cpp-guidelines` applies the guidelines to code.
  `refresh-guidelines` refreshes sources, imports research reports and checks
  links.
- **Evals** ([`evals/`](../../evals/README.md)): a pilot of 21 cases on
  ownership and lifetime, for comparing an agent with and without the
  `cpp-guidelines` skill.
- **Branches:** `dev` is the integration branch, and `main` holds releases
  only ([#85](https://github.com/homer6/cpp-docs/pull/85)).
- **Version:** `project(VERSION 0.1.0)` in `CMakeLists.txt`. The test
  `release_notes_exist` fails when the notes for that version are missing.

## What it does not include

- **Not checked on MSVC or Windows.** Every claim was checked on macOS arm64
  (GCC 15, Clang 22 with libc++) and on Linux arm64 (GCC 16 in Docker).
- **Features no local compiler implements yet** are documented with a
  `needs=` tag and a skipped test, not verified. These are `std::hive`,
  senders/receivers, `std::linalg`, `std::simd`, RCU and hazard pointers, and
  the private module fragment. GCC 16 covers contracts, reflection, expansion
  statements, `inplace_vector`, `mdspan` and `<stacktrace>`; GCC 15 and Clang
  22 skip those tests.
- No packages or build artifacts. The deliverable is the documentation.

## Known issues

No security-relevant issues. No issues are open.

- **Clang 22 + libc++:** 12 snippets fail on genuine libc++ gaps (for example
  `std::generator`, `text_encoding`, `move_only_function`, `syncstream`, chrono
  time zones and special math functions). They are listed in
  `tools/snippet_baseline/clang.txt`, and the list should only shrink. The GCC
  baseline is empty.
- **Homebrew GCC 15 on macOS:** `std::nested_exception` doesn't capture the
  current exception, so `ThrowTryCatch.NestedExceptionsPreserveCause` skips.
- **The GCC 16 Docker run** uses Debian's CMake 3.31, where `import std` is
  still experimental, so the three `import std` tests skip there. They run
  under CMake 4.3 on macOS.
- **Locale tests** skip where the platform has no `de_DE` or `en_US` locale.
- **No CI.** GitHub Actions is disabled, and the proof below is from local
  runs.

Fixed while cutting the release: the examples index footer no longer says
cppreference is the only source
([#87](https://github.com/homer6/cpp-docs/pull/87)).

## Where it has run

- macOS 14 (arm64): Homebrew GCC 15.2.0, Homebrew Clang 22.1.8 with libc++,
  CMake 4.3.
- Linux arm64: Docker `gcc:16` (GCC 16.2) with Debian's CMake 3.31.
